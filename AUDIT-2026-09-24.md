# MMM audit — 2026-09-24

Audited: the whole MMM app at commit `ecd9c9e` (about 4,300 lines: native shell, web UI, wallet plumbing, mining engine, build and install).
Method: 7 specialist reviewers found 69 issues. An independent skeptic then tried to refute each one. **60 survived: 1 high, 23 medium, 36 low. 9 were refuted.** Reviewers overlapped, so this is about 50 distinct bugs, merged below.

No critical issues. Nothing found lets a remote party take wallet keys or send coins without your Touch ID. The main risks are **crashes an explorer or pool can trigger**, a **memory leak in long mining runs**, and **wallet-tab states that break sends**.

## High

| # | Where | Problem | Fix |
|---|---|---|---|
| H1 | Engine `main.swift:1302` | The mining loop never frees temporary Metal and JSON objects (no autorelease pool), so engine memory grows without limit over long runs. | Wrap each loop iteration in `autoreleasepool`. |

## Medium — crashes from bad explorer data

| # | Where | Problem | Fix |
|---|---|---|---|
| M1 | `App.swift:73` | An explorer reply containing a number like `-1e309` becomes `-infinity`. MMM can't pass that to the page, so it breaks on every refresh, which starts at launch. | Validate JSON before use; invalid replies take the "explorer offline" path. |
| M2 | `App.swift:163` | A block height near the integer minimum overflows and crashes MMM (reproduced). | Only accept heights ≥ 0. |
| M3 | `App.swift:367` | Huge UTXO amounts overflow the balance sum and crash the WALLET tab (reproduced). | Bounded, overflow-checked sums; bad data shows "unavailable". |
| M4 | `App.swift:141` | A web file dropped onto the MMM window replaces the page and gets the native bridge. It could change your payout address without Touch ID. Sends still need Touch ID. (One skeptic disagreed; fixing anyway.) | Allow only the bundled page; block drag-to-load. |

## Medium — mining engine

| # | Where | Problem | Fix |
|---|---|---|---|
| M5 | `main.swift:717/778` | When the pool closes the connection, the engine is killed by a broken-pipe signal (SIGPIPE), so its reconnect logic never runs. | Ignore SIGPIPE on the socket. |
| M6 | `main.swift:810` | Share submissions aren't JSON-escaped. A worker name containing `"` or `\` silently loses every share and block. | Proper JSON encoding. |
| M7 | `MetalDAGEngine.swift:211` | Every 14 days (DAG epoch change) the old DAG is kept while the new one is built, doubling memory; a failed allocation crashes. | Free the old DAG first; handle allocation failure. |
| M8 | `main.swift:1207` | Startup failures exit with "success", so MMM just says "Mining stopped." | Nonzero exit codes; the GUI shows the reason. |
| M9 | `main.swift:1305` | While the pool is down, the dashboard keeps showing the last hashrate, and "reconnecting" never reaches the GUI. | Zero the stats while disconnected; report status. |
| M10 | `StatsServer.swift:357` | The stats server doesn't check the Host header, so a malicious web page using DNS rebinding can read your mining stats. | Reject requests whose Host isn't loopback. |

## Medium — wallet tab

| # | Where | Problem | Fix |
|---|---|---|---|
| M11 | `App.swift:330` | Cached wallet addresses ignore the network: on mainnet the tab shows the testnet `txa1…` address as unlocked. | Cache per network, file and key index. |
| M12 | `App.swift:447` | Re-creating a wallet file at an old path shows the previous wallet's address as unlocked. | Invalidate the cache on create. |
| M13 | `App.swift:473` | Card wallets without a passphrase (older format) can't be unlocked or spent from. | Require a passphrase only for formats that need one. |
| M14 | `App.swift:346` | A stale "has passphrase" flag hides the send passphrase field, so the send can never succeed. | Derive that flag from the file's current state. |
| M15 | `app.js:129` | Switching wallet file overwrites that file's saved key index with the previous file's index. | Keep index per file. |
| M16 | `app.js:24` | Important wallet and engine messages vanish within 15 seconds and are cut off. | Keep errors visible, full text. |

## Medium — packaging

| # | Where | Problem | Fix |
|---|---|---|---|
| M17 | wallet launcher | Without Homebrew Python, the launcher falls back to Apple's Python, which can't open `.mmm` wallets. Every wallet action fails for such users. | Detect it and show a clear "install Python" message. |

## Low (grouped)

**Security hardening**
- The Touch ID send prompt shows only the first 12 characters of the destination. It will show the full address.
- The companion-token redaction can leak the token into COPY LOG when a line arrives split across two chunks.
- The forum sign-in opens a server-supplied URL without checking it. It will allow only https links to minedifferent.com.
- Any browser extension, not just NerdMiner's, can authenticate to the stats server by its Origin.
- Pool-controlled values can cause crashes or stalls: the epoch picked from nTime, an extranonce2 size overflow, an unbounded receive buffer, and terminal escape sequences in log output.
- Identicons do unbounded work for untrusted addresses.
- NUKE forgets only one saved pool password.

**Bugs**
- Out-of-order wallet refreshes can show stale data.
- There's no overall request timeout, so the app can stay "busy" forever.
- NUKE can race a miner that is just starting.
- There's no recovery if the web view crashes.
- DAG build errors are ignored.
- Share counts include the authorize reply, and the reject reason always reads "unknown".
- A CLI error message over 64 KB deadlocks the app.
- NEW WALLET status sticks on "WORKING…".
- The "miner pending" message is ignored, so the dashboard shows stale data.
- SETUP updates the display before the save is accepted.
- Amounts with a decimal comma are rejected with a misleading error.
- At small window sizes, the SETUP panels overlap the engine log.
- In dark mode, COPY hover text is nearly invisible.
- The heading reads "WHENYOU ARE".
- The JS view tests are broken since the 6-tab change.
- The wallet CLI can leave a 0-byte `wallet.mmm` if encoding fails (in the xcoin-wallet repo).

**Build and install**
- A missing wallet source silently re-bundles a stale CLI.
- An apostrophe in a path breaks the build.
- File extended attributes (xattrs) break code signing.
- The step counter shows "[6/5]".
- install.sh installs a half-built bundle, and merges into the old app instead of replacing it.

**Also found during the session:** the "kill wallet processes on quit" fix didn't fire in one case. A card unlock was left stuck on the reader after MMM restarted. It will be investigated with the native fixes.

## Refuted (not fixed)
- Plain-http explorer MITM and the network check failing open. Both are covered by the existing hrp check and by Touch ID on sends.
- Login signing any challenge. The 65-byte floor and the fixed message template already constrain it.
- The key index being read after Touch ID. It's already guarded.
- The seed being shown in a hidden tab.
- Ad-hoc signing forcing Keychain re-prompts. That's inherent; a stable fix needs a real signing identity.
- The orphan-process installer check, and the minimum-macOS mismatch.

## Plan
Four fix groups run in parallel, each owning its own files: native shell, web UI, engine (mirrored to the NerdMiner repo), and build/install/wallet launcher. Then a full build, the test suites, a check of each fix, install to the Dock, commit and push.
